Use `Cache-Control: no-store` throughout, including public wall reads at launch so moderation changes are visible on the next fetch.

`Rail` is `payos | polar`. IDs in the following shapes are UUIDs. `Status` is `{ id, rail, status, amountMinor, currency, presetCount, expiresAt, paidAt }`, with nullable fields where appropriate. `Checkout` is `{ status: Status, checkoutUrl, qrCode, transferNote }`, with the last two fields null for Polar. `receiptKey` is a browser-generated 32-byte base64url secret. Use indistinguishable `404` responses for an unknown donation or wrong receipt key.

### Payment lifecycle

- Reserve the donation before calling a provider. The browser retains the same UUID and receipt key across double-click, network retry and refresh. In D1, bind the normalized payload fingerprint to the ID and key. Only the reservation winner sends a provider create request. Successful authenticated replays can retrieve the prior result without spending another Turnstile challenge. Generate a new ID only for an explicit new attempt. Persist the provider binding before returning any payable QR or checkout URL.
- `creating → pending` follows a validated provider create response. `creating → failed` follows a definite rejection. `creating → creation_unknown` follows a timeout or uncertain response. Use a creation deadline for crashed requests so they become recoverable as unknown. The documented PayOS lookup does not provide the QR or checkout URL needed to reconstruct a lost create response. Keep the original receipt available for status rechecks and verified late webhooks, and offer an explicit new attempt with guidance to avoid paying twice. For uncertain Polar creation, avoid issuing a second checkout for that attempt. Allow a matching verified webhook or operator reconciliation, and give the visitor a clear status and an explicit new-attempt action if no checkout was delivered.
- A confirmed terminal provider failure can write `failed`. A pending checkout becomes effectively `expired` at its deadline (use server time and an atomic condition if persisting it). A visitor leaving checkout or landing on a cancel URL is a presentation hint. Verified paid evidence wins over any unpaid state, including expired or apparently failed attempts. Once paid, preserve the original `paid_at` and prevent later failure, duplicate events or browser returns from demoting it. Use Worker-observed confirmation time for review token expiry.
- Browser receipt polling reads the Worker every 2–3 seconds while QR or confirming is visible. Pause in hidden tabs, recheck on visibility change, stop on paid, and back off on failures. At QR expiry hide the QR and offer a manual status check or a new attempt. Late webhooks still settle the old row. Give Polar a short bounded sequence of confirmation requests with backoff and a manual “Check again”; do one bounded upstream read per request. Use the same D1 settlement path for webhook and checkout verification.

On return, look up the bound checkout ID using the server’s token. Require a match to the stored donation, expected org/product, USD amount before taxes and attempt metadata. [Polar checkout retrieval](https://polar.sh/docs/api-reference/checkouts/get-session), [Polar webhook validation](https://polar.sh/docs/integrate/webhooks/delivery), [Standard Webhooks specification](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md)

Settle only a verified `order.paid` with paid status and matching checkout, org/product, donation metadata, currency and exact pre-tax price. Validate zero discounts and match subtotal and net amount to the planned USD donation. Check the authenticated checkout if the event lacks a required binding field or the stored checkout ID has not been written yet. Use the event ID for replay protection, checkout/order uniqueness for underlying payment identity, and the shared conditional update for the webhook/return race. A freshly signed delivery can settle an older payment after expiry. A stale signature fails timestamp verification. [Polar order.paid payload](https://polar.sh/docs/api-reference/webhooks/order.paid)
